# MiniDB — File-Based Database Engine

Учебная файловая мини-СУБД на Python, реализующая базовые операции управления данными без SQLite, сторонних СУБД и ORM.

MiniDB поддерживает создание таблиц, CRUD-операции, фильтрацию записей, первичные и внешние ключи, JOIN, файловую персистентность, индексирование по первичному ключу и Backup / Restore.

## Возможности

- **Custom file storage** — хранение таблиц в собственном файловом формате.
- **CRUD** — добавление, чтение, обновление и удаление записей.
- **Filtering** — условия `=`, `!=`, `>`, `<`, `>=`, `<=`, объединение через `AND` и `OR`.
- **Primary Key (PK)** — уникальный идентификатор и автоматическая генерация ID.
- **Foreign Key (FK)** — проверка ссылочной целостности.
- **JOIN** — получение экспериментов вместе с названиями датасетов и моделей.
- **Indexing** — индекс `id → byte offset` для поиска записи по первичному ключу.
- **Persistence** — сохранение данных между запусками программы.
- **Backup / Restore** — создание резервной копии и восстановление базы.

## Формат хранения

База данных представлена каталогом с файлами:

| Файл | Назначение |
|---|---|
| `schema.txt` | Описание таблиц, столбцов, PK и FK |
| `meta.txt` | Метаданные, включая счётчики следующего авто-ID |
| `<table>.dat` | Записи таблицы в собственном текстовом формате |
| `<table>.idx` | Бинарный индекс первичного ключа и смещения записи в `.dat` |

В файле `.dat` каждая запись занимает отдельную строку, поля разделяются символом табуляции, а обратная косая черта используется для экранирования.

После операций `INSERT`, `UPDATE` и `DELETE` индекс перестраивается заново.

JSON не используется как основной формат хранения строк таблиц.

## Индексы и benchmark

Для поиска по первичному ключу реализован индекс `id → byte offset`. Он позволяет определить позицию записи в файле и прочитать её без последовательного сканирования всей таблицы.

Запуск benchmark:

```bash
python benchmark.py
```

Результаты локального тестирования:

**Test setup:** 1 000 записей, 200 поисков по ID, 5 повторов.

| Метод | Min (с) | Avg (с) | Max (с) |
|---|---:|---:|---:|
| Sequential scan | 0.3191 | 0.3272 | 0.3371 |
| Indexed lookup | 0.00510 | 0.00563 | 0.00629 |

**Average speedup: 58.1×.**

Результаты зависят от оборудования, размера таблицы и набора запросов. Для воспроизведения используй `benchmark.py`.

## Backup / Restore

Создание резервной копии:

```bash
python main.py backup data data_backup
```

Восстановление в отдельную директорию:

```bash
python main.py restore data_backup data_restored
```

Restore выполняется в новый каталог, чтобы не перезаписывать существующую рабочую базу.

## Python API

MiniDB можно использовать напрямую из Python:

```python
from minidb import MiniDB, Condition, Filter, init_default_schema

db = MiniDB("data")
init_default_schema(db)

db.insert("datasets", {
    "name": "Test",
    "task": "cls",
    "size": 100
})

rows = db.select(
    "datasets",
    columns=["name", "size"],
    where=Condition("size", ">", "50")
)
```

Получение экспериментов с названиями связанных датасетов и моделей:

```python
rows = db.experiments_with_names()
```

## Ограничения

- Нет полноценного SQL-парсера.
- Не реализованы транзакции и многопользовательский доступ.
- `SELECT` и фильтрация читают таблицу целиком.
- `UPDATE` и `DELETE` перезаписывают файл таблицы.
- Индекс поддерживает поиск по первичному ключу `id`, а не произвольную фильтрацию.
- Производительность зависит от размера таблицы и количества операций перестроения индекса.
